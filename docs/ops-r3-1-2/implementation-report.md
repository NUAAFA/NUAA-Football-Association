# OPS-R3.1.2 实施与验证报告

2026-10-01。本轮基于 `86658c6838dfe93b93147bb0ce34e00acf5ca228`，工作分支 `codex/ops-r3-1-1`。交付是当前未提交的工作区变更，不代表该基础提交已经包含 R3.1.2。

## 实施结果

正式对阵与排期已经解耦。`Match.kickoff`、`Match.venue` 可为空；内部比赛状态仍为 `SCHEDULED`，时间或场地不完整时后台显示“待排期”。旧字段、旧比分、版本、裁判记录均保留。

- 后台比赛列表、赛事工作台和详情显示待定事实，并提供“安排比赛”轻量表单：日期、开球时间、可选结束时间、场地。保存仅改变排期，不自动开放报名；完整编辑入口保留。
- Service/API 阻止待排期比赛开放报名、提交执裁意向（包括管理员例外）、发布选派、确认赛果和完成选派。已有正式任务时禁止清空时间或场地。数据库触发器进一步阻止待排期比赛开放报名或变为 `COMPLETED`。
- 时间冲突判断跳过排期不完整的比赛。公开报名页和正式裁判任务排除待排期比赛；旧完成记录仍在个人历史中保留，并按现有规则提示事实待核。
- 首页下一场只查询有开球时间、`SCHEDULED`、开球时间不早于当前时间的比赛。正式对阵全部待排期时，公开端显示“赛程已公布，具体比赛时间待定”。完整公开赛程保留对阵及“时间待定 / 场地待定”。
- DOCX 的合法小组赛对阵允许空日期、时间、场地，返回黄色“比赛时间待安排 / 比赛场地待安排”，支持原子提交。非法日期、只填写日期或时间、无效结构/球队/场序继续阻止提交。重复待排期导入按结构、场序及双方识别，不重复创建。
- `CompetitionGroup.name` 为普通字符串（1–80 字符），同阶段唯一；组数没有 4 或 16 的上限。新增组时间字段，维护名称、顺序、人数、未分组名单、多选批量分配/移回/合法换组。
- 多组采用可搜索网格、16 项一页的小组目录、30 项一页的球队列表；16 是分页大小。赛程和积分使用动态 Select，公开积分同时支持搜索及折叠目录，按赛事/阶段/小组隔离。
- 正式比赛、积分/赛果、排名及出线确认参与换组检查；危险修改默认阻止，前端先明确警告。旧成员维护接口也保留同样的历史保护。
- DOCX 按已有小组名称动态匹配 H组、L组、自定义名称；未匹配组不会自动创建。分组不一致显示具体组名及逐个球队名称。Preview 内提供分组修复 Modal，文件和行修改留在当前页面，修复后直接重新检查。刷新整页或主动切换输入会话仍需要重新选择文件。
- 沿用现有积分、排名/出线确认和手工淘汰赛流程，不自动推进淘汰赛、不创建占位球队。本轮没有开发自动排程系统或导入后批量排期系统。
