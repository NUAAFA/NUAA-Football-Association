3. 校验与导入契约

操作员必须从经过认证并审核的 GitHub Actions run summary/log 独立取得
准确 commit 和 tar.gz SHA-256。不能仅从下载包或其 sidecar 取得信任值；
upload-artifact 外层 ZIP 的 digest 也不能替代这里的 tar.gz digest。

命令形式（本轮未对生产执行）：
nuaafa-deploy --import-artifact <绝对归档路径> --artifact-sha256 <独立64位SHA256> --allowed-ref <明确refs/heads/...> <40位commit>

导入在全局部署锁内执行，先做有界私有副本和外部摘要校验，再验证归档。
仅接受规范的相对路径、普通文件和指向 node_modules 内普通文件的 npm bin
相对链接。拒绝绝对路径、..、歧义分隔符、控制字符、重复条目、Git 元数据、
敏感/可变路径、硬链接、设备/FIFO、目录链接、危险符号链接、特殊权限、
额外/缺失条目及内容不符。解包不调用 tar.extract 或 extractall。
有文件数、压缩输入/展开大小、单文件限制以及 512 MiB 磁盘安全余量。

随后从固定仓库取得准确 commit，确认其可从 allowed-ref 到达，将候选内容
放入临时 releases 目录，逐个比对 Git 源文件与归档文件，校验依赖和完整闭包。
只有全部通过才发布版本目录。失败删除临时目录，不覆盖已有同 SHA 版本。
重复导入只有在 receipt、来源和所有运行文件仍一致时才复用；冲突直接拒绝。

校验 receipt 位于 /srv/nuaafa/prebuilt/<commit>.json，root 控制，位于版本
目录之外；它绑定独立 SHA、commit、ref 和已验证文件清单。
receipt 先写，版本目录后原子改名；中途异常最多留下一个禁止自动复用的
orphan receipt，需要运维调查，不会产生无标记的可激活版本。
内部 manifest 仅用于枚举和附加校验，不能单独建立信任。

4. 激活与生产隔离

导入不连接 shared/.env.production、prisma/dev.db，不读取 shared 数据，
不运行候选代码，不执行备份/迁移，不切换 current，不操作服务或上传目录。
归档与展开副本均位于可清理的私有临时目录。

该批准记录必须同时准确绑定 commit、tar.gz SHA、allowed-ref，并明确含
security_gate=PASS、linux_artifact_validation=PASS、human_review=APPROVED。
产物内 release_allowed 固定 false；任何产物内自我批准声明均会被拒绝。
工具不产生批准文件，不接受异常字段，也不自动批准任何漏洞例外。

第二次学号预检、运行文件复核、原子切换、重启及健康验证。
重启/健康失败恢复旧版本链接并尝试重启旧服务；不反向回滚数据库迁移。
