# 新闻关联赛事与赛事报道 · 2026-10-23

分支：`codex/competition-news-links`。基于本地已知 `origin/main` / `5c86ad7`，独立工作区；未更改另一个赛事展示工作区中的未提交改动。

## 原因

动态赛事详情原先直接输出“暂无赛事报道”，不查询已发布新闻；普通新闻表和后台表单也没有赛事关联字段。原有 `DisciplineDetail.competitionId` 只用于纪律决定，不能作为普通新闻的赛事关系。截图的 3138 / presentation-cup 属于另一个隔离模拟预览，不能据此判断生产数据库同步状态。

## 最终行为

- 新闻编辑增加“报道所属赛事”，明确选择具体赛事 ID，不根据标题、年份或“新生杯”关键词猜测。
- 已发布的新闻和公告按原始发布时间倒序显示在对应动态赛事详情；同一时间按 ID 排序。
- 草稿、归档、未来发布时间、其他赛事、未公开或测试赛事的内容不会混入公开列表。
- 后台改绑、解除关联、改变发布状态后，赛事详情重新读取数据；写接口同时使赛事详情路径失效。
- 旧客户端省略新增字段时保留现有关系；明确传 null 或空字符串才解除关联。
- 服务端校验赛事存在且非测试赛事，保留内容权限和同源校验，事务记录关联前后的操作日志。
- 新迁移只新增可空外键列和索引，旧文章默认为未关联；删除赛事不会删除新闻。
- 原有静态档案的人工编排报道保持原状；新查询服务于数据库驱动的赛事详情，且只在数据库新闻模式启用。

## 赛事影像补充

赛事详情和全站影像资料页读取已关联、已发布报道中的媒体库图片，去重封面及正文引用。仅 PUBLIC 的 JPG / PNG / WEBP 会展示，保留媒体说明与报道来源、原图及相关报道链接。撤回来源报道、改绑赛事或将照片设为 PRIVATE 后，公开相册随之更新。未上传视频时不生成视频内容。

上线涉及第 19 条精确迁移，可信发布工具增加该 SQL 与完整 schema 的摘要白名单，保留旧 17/18 条版本验证；未知或改动过的迁移仍拒绝。附带 18→19 的真实 SQLite 演练及前后内容保持测试。CI 检查覆盖新功能，并在合并 main 后验证最终提交与生成对应 Linux 包。
